# Probashi Footballers - Project Context

## Project Overview

Probashi Footballers tracks football players of Bangladeshi heritage playing outside Bangladesh.

Primary goals:

- Discover and track diaspora players
- Maintain a community-driven database
- Present data through a lightweight static website
- Preserve historical records
- Minimize maintenance overhead

Website repository:

https://github.com/dr-shiffles/probashi-footballers

---

# Current Architecture

## Hosting

- Source Control: GitHub
- Frontend Hosting: Cloudflare Pages
- Website Type: Static Website
- Frontend: HTML, CSS, JavaScript
- Database: CSV files

## Production Data Files

The website currently uses:

data/mens.csv
data/women.csv

These CSV files are the authoritative production files used by the website.

# Automated Files

## lastUpdate.json

Location:

data/lastUpdate.json

This file is automatically generated by GitHub Actions.

Workflow:

.github/workflows/update-timestamp.yml

Purpose:

- Store latest update timestamp
- Store player counts
- Display "Last Updated" information

IMPORTANT:

The AI must NEVER edit:

data/lastUpdate.json

This file is automatically generated.

# Data Sources

The database is compiled from:

- Official club websites
- Club rosters
- Football federation registrations
- Match reports
- Scouting reports
- Agent information
- Social media accounts
- Community submissions
- Public databases

All information should be treated as potentially outdated until verified.

---

# Design Philosophy

Keep the website simple.

Preferred:

- CSV
- JSON
- Static HTML
- JavaScript
- GitHub
- Cloudflare Pages

Avoid unnecessary complexity:

- SQL databases
- Backend APIs
- React
- Next.js
- Microservices
- Server infrastructure

The project should remain maintainable by a single volunteer.

# Future Data Cleanup

The project currently contains players with uncertain status.

Preferred categories:

- Active
- Inactive
- Status Unknown
- Retired
- Duplicate
- Needs Verification

Do not permanently delete records unless explicitly requested.

Historical information should be preserved whenever possible.

# AI Objectives

The AI should help:

- Extract player information
- Compare records
- Find duplicates
- Detect changes
- Organize data
- Validate records
- Generate CSV rows
- Summarize updates

The AI should not:

- Modify deployment workflows
- Modify lastUpdate.json
- Introduce unnecessary technologies
- Delete historical information without approval

## Update Reports

Database updates are summarized in changelog files.

Purpose:

- Internal history
- Source for social media posts
- Historical audit trail

Preferred format:

changelog/YYYY-MM-DD.md

The AI should help generate and maintain changelog files whenever updates are made.

Screenshots used on social media are temporary artifacts and do not need to be stored.
